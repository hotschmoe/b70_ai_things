# SDK37 executable and upload-oracle byte epoch prototype

CONFIG

Root actual typeprobe1992 closed representation diagnosis in559 seconds after
pack epochs removed repeated dense-pack digest work. Its bounded FD sample
observed repeated SDK37 eight-ELF and source-upload-oracle reads; this does not
claim complete FD/interval coverage or physical read bandwidth. Actual pack
witness logged3080 semantic digest calls. H48 correctness/actual admission is
separate and remains unchanged by this prototype.

operation_sdk37_byte_witness_v1 targets exactly eight source37 build targets
and the associated upload oracle. Source37 compiled_source_markers checks
source text; it does not scan executable markers. Source39 has additional
actual executable marker checks and would need its own declared later adapter.
This prototype does not invent or replace a source37 binary-marker scan.

COMMAND

PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=strata/flash-next python3 -m unittest test_operation_sdk37_byte_witness_cpu_v1

Prototype API (future root-owned byte execution only):

roster, receipts = metadata_roster(GENUINE_PREPARED_JSON)
epoch = SDK37Epoch(roster, receipts, max_seconds=DECLARED_BOUND)

Every future semantic consumer must authenticate its current complete expected
roster and receipt inputs with require_current_roster. It may then call named
digest_for/ELF_magic APIs. Root must seal_predevice before any device/health
work and finalize after operation. The child creates its own fresh epoch and
never imports parent success. No save/load proof constructor is provided.

RESULT

Ten CPU controls pass using tiny temporary ELF-like byte fixtures/receipts.
The80-call control performs exactly27 full byte scans: nine members at each
entry/predevice/post boundary. Negative controls cover data/receipt mutations,
missing/duplicate/wrong role, wrong expected SHA, non-ELF matching-digest bytes,
foreign PID, expiry, unsealed/closed phase and unknown semantic caller.
Oversized metadata is rejected by statsize BEFORE any read; bounded FD reads
also refuse growth and stat/descriptor changes. No actual SDK binary, pack,
model or runtime is read/executed by agent.

Each complete byte scan verifies SHA, actual ELF first4 bytes, count and
path/descriptor stat5 before/after. Receipt metadata is fully read and SHA/
stat5 checked at every semantic roster join and byte boundary, with at most
16MiB per receipt (pre-read cap), two through eight distinct receipts. SDK
receipt/plan/oracle metadata association is a factory prerequisite; it is not
standalone model/runtime/semantic qualification. The actual existing source,
header, patch, ABI image, recipe, upload, library, health, originalall4/pages,
EOF and owned teardown checks remain required independently.

Post-seal semantic calls may consume the operation's in-memory byte result
before its mandatory fresh final scan. Changes across boundaries fail even
if expected content is restored but stat5 differs. Mutation between complete
read boundaries remains explicitly unobserved, not a stat-only guarantee.
Ownership is one PID and a declared lifetime of at most10800 seconds.

Integration requires a NEW deliberate source generation threading sdk_epoch
through each real engine_binding/combined_generation_gate/validate_prepared
executable digest and original_upload_gate oracle digest/magic consumer.
No module.sha monkeypatch, saved-digest reuse, fake baseline view, invisible
fallback or source/recipe gate removal is allowed. SDK/source receipts and
all ordinary small source/header checks remain intact. The prototype is
currently unintegrated and carries full_semantic_admission_proven false.
