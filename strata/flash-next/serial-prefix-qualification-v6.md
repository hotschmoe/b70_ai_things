## Observations added by0019

STRATA_PREFIX_LIFECYCLE_DIAG=1 additionally requires the existing ARM file and
supported serial text PrefixDiagnostic scope. Default off adds no model kernels,
graph nodes, queue waits, tensor copies or cache-selection/reset changes.
Cache records carry exact source-token SHA256, semantic snapshot metadata SHA256,
and a unique observed admission instance. The bounded fixed host registry follows
instances through deque erase/movement without changing SavedConversation layout
or charging metadata as model snapshot bytes. Unobserved pre-ARM instances,
registry overflow, truncated descriptors and skipped observations cannot supply
exact victim proof. Semantic metadata hashes include geometry, steering, live and
checkpoint tokens/image keys/pins and stage metadata; they are not raw state-byte
hashes. Empty live vectors use the deepest checkpoint for source-token provenance.

Successful admit/take/evict/superseded and put refusals report actual retained
bytes/entries/budget/slots/held plus stage ranges. Estimated-budget and physical
RAM refusals are separately keyed skipped observations. Snapshot estimation,
allocation failure and some validation refusal paths still lack keyed events;
all_admission_refusals_observed remains false. No model payload is dumped.

committed_live follows the original publication guard and existing recursive
commit wait. It records canonical source token IDs/digest, chain_updated,
live_reusable and published=chain_updated&&live_reusable. Thus ckpt0 cannot be
reported reusable merely because the chain was updated. Cancellation phase
prefill/decode reflects the actual source path, not when the client sent STOP.
No zero-work claim is made for cancelled/partial device operations.

Each ordinary verifier stage reports actual body entry/return spans. Each
prefill stage counts completed chunks and reports complete only if all requested
n rows reached its final body return. Cancelling or failing before that point
cannot report the whole span complete. These use existing source waits and do
not prove commit completion independently. V6 checks matching entry/return,
actual configured stage/device/ranges and exact prompt work per stage; it does
not substitute the older topology-derived multiplication for observations.
Scope is serial,64 armed requests and4096 events/request; V6 allows at most six
armed requests/process and fails skipped/missing coverage. No concurrency claim.

## Separate bounded request groups

Existing V5 groups remain separate bounded controls. V6 adds:

- cancel_decode: fresh same/unrelated references, actual decode STOP, nonfresh
  same replay, nonfresh unrelated replay, fresh unrelated confirmation (six).
- cancel_prefill_isolation: the analogous six requests using the useful longer
  inventory prompt; actual phase must be prefill, otherwise the intended gate
  remains unobserved and fails.
- real_live: natural seed, fresh actual-assistant/new-user continuation, identical
  seed again, nonfresh continuation (four). Output IDs and decoded assistant text
  must match. Render through the exact tokenizer/template and require actual
  committed IDs to be a strict valid prefix; never rewrite tokens to manufacture
  a live hit. Require live route/exact reused boundary and unchanged numerical
  comparisons. A retokenization mismatch is an explicit unsupported point.
- eviction: the existing six requests now require the target's successful
  observed admission and exact instance/metadata victim identity before its cold
  replay, plus observed512MiB/one-entry budget checks. A target never admitted
  cannot qualify as evicted merely because another global eviction occurred.

ARMED_REQUESTS is checked before every submitted armed GEN and checked for exact
roster completion. Basic uses three; all other existing groups use six. Unarmed
warmups, cache geometry, max64 generation, natural finish, bitwise finite first
logits/all48 residuals, exact IDs/LP20 and teardown remain fixed. True flag0 has
no raw logits/lifecycle capture and is explicitly unobserved at that scope.
