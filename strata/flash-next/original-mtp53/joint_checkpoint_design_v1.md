# Atomic paired-target/original checkpoint ownership

CONFIG -> New default-unintegrated source headers against actual SDK58. One
immutable move-owned object retains BOTH SavedConversation stage images,
complete original payload, exact PLE previous-token metadata, and full older
compound branches. No target/original math or legacy file schema changes.

COMMAND -> At actual park_slot frozen RID/gen boundary, capture BOTH stage
snapshots with nullptr legacy draft, then complete original checkpoint at the
SAME accepted prefix. Recheck owner before constructing/publishing. Digest
includes actual geometry/carves/cvec, ids/images/retention metadata, ALL recurrent
GDN/PLE/indexer/checkpoint vectors, ALL k/v/scales/pooled bytes via visit(), PLE
host metadata and original payload digest. Existing metadata-only digest is not
used. Older checkpoints require a saved complete compound branch with matching
running state and source contract; never truncate later original banks.

RESULT -> Cache owns shared_ptr<const compound>. Move/publication/eviction never
split original from target. Lookup requires exact draft/target contracts and
matching accepted prefix. Weak OWNERSHIP registry charges held payloads even
when their cache root is evicted; no token-only side map. Branches/parent graphs
are bounded and strictly shorter, so no ownership cycles. Byte accounting is
conservative and must be combined with actual capture/RAM admission.

Persistent schema is a NEW atomic directory: SDK-validated per-stage files,
original complete LE file, PLE metadata, manifest and recursively owned branch
directories. Exclusive staging/no-replace rename publishes the whole bundle;
parent flush status is explicit. Readers require independently pinned joint
hash and bounded actual SessionReadLimits with RAM admission. Exact roster,
opened-file identity, original hash and reconstructed FULL joint digest refuse
partial/replaced/mismatched data. Existing standalone legacy session file readers
are not authorized to call this a complete original cache entry.

Restore prevalidates original/destination owner and BOTH actual target snapshots
before writes. Then original target restore/drain/recurrent+KV byte verification
and complete original import occur at the same serialized boundary. Any failure
after first write exits86 before library destructors; never fallback from partial
state. Only AFTER all succeed may caller activate BSlot/HTTP/cache state. Caller
must freeze slot generation throughout; API concurrency is not qualified here.

ABI: prototype adds only new headers/TUs; existing target public headers/layouts
remain unchanged, so standalone compile may link genuine58 archives. Production
wiring must replace the cache OWNER/type and serve-loop hooks coherently; adding
fields to SavedConversation/SessionState/Verifier would require FULL fresh SDK
header-consumer builds, never reuse old123 objects across a changed ABI. This
prototype does not grant that integration or runtime/API/speed authority.

Native CPU fixture implements payload-digest mutation, complete older-branch,
source-matched lookup, hold/evict/byte-charge behavior. File helper and real target
capture/restore signatures are included for native compile; file roundtrip and
actual target/GPU behavior are not claimed until root executes them.

reset/full-bank/head/owner checks, then advances saved5->9 across compression8
