ONE NEXT MECHANISM TO PREPARE IN PARALLEL: batch GDN commit across layers

Observation (source/S136):
- Commit issues `gdn_step_norm_multi` 72 times (36 layers \xd7 2 owner groups) and `gdn_conv_commit` 72 times.
- Each call is independent per layer and owner (its own state, conv history, qkv/h/gate/beta slices and keep vector).
- Each replays the accepted prefix and stores one final state.

Proposal (source-only for now): a new kernel class, layer-batched, reusing the existing per-layer body unchanged. Pass a small device table of per-(layer, owner) pointers and keep pointers, with grid.z = layer and owner.
- Each work-group executes exactly the existing per-layer arithmetic and order, so the FP ledger per cell is unchanged by construction. There is no cross-layer reduction.
- Batch conv commit the same way: a copy-only selection.
- This replaces up to 144 graph nodes with about 2\u20134.

Required source fix found while auditing: every layer's call writes the same `y_dummy_ + first*ZV`. That is harmless when serial but becomes a write race when batched. Give each layer its own dummy slice, or add a no-output variant; only if the output is provably never read.

Smallest strict GPU-first discriminator: a private fixture with 36 synthetic layers \xd7 2 owners at real dimensions (state 128\xd748\xd7128 floats, conv history, keep 1..3, rejected suffixes). Compare the existing per-layer calls against the batched kernel on:
- complete state bytes;
- conv history;
- guards;
- read-only inputs;
- finite values;
- eager and captured A/B/A.

Stop at the first mismatch. Only then, one completed whole-commit-chain timing.

Stop conditions:
- the existing GDN step kernel uses per-launch shared or global scratch that cannot be duplicated per layer;
- its launch geometry or register footprint cannot accept an extra grid dimension without changing the body;
- the commit graph's tail snapshot or PLE sequencing would need reordering.

In any of these cases, keep the per-layer path and drop the idea.

Deferred: verifier HC, routed and Q6 pools (S125 needs +488 MB and two launches), until commit batching and the S143/S139 results are in.
