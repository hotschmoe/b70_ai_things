## Source checks

| Area | Finding |
|---|---|
| Recorded sequence | Bodies are copied verbatim from the three component captures. Order on `cs_` is round 0 (T0), round 1 (T1), tail 0, step 0 (j=1), step 1 (j=1), tail 1. This matches the OFF launch order at `max_steps == 2`. S103 showed in-order recording keeps linear edges. |
| Cache key | `pair_exec_[T0][T1]` uses the *effective* T, after the catch-up-all policy. Depth is fixed at 2 by the `max_steps == 2` gate. The component caches are keyed the same way (`[c][T]`, `[c][j]`, `[j]`), so no new aliasing is introduced. Index bounds are 1..8 within 9. |
| Fresh mapped data | The same `copy_from_mapped_multi` copies are recorded and re-read on replay, exactly as in the component graphs. Staging and the `seq_cst` fence still come before the single launch. |
| Shared scratch | `xq2_` and `logits2_` are used by tail 0 then tail 1 in the same serialized graph, as before. |
| Lifetimes | `pair_exec_` is deleted after the `cs_` drain and before the component graphs and scratch. The pair is still destroyed before the drafters. The external `slot_mtp_rows` lifetime is a pre-existing point that is not made worse, because no graph runs during teardown. |
| Polling/PLE | Unchanged. It runs after the submit, against the same `h_out_` records and in the same depth order. |
| Failure | Capture or launch failure returns false. The existing caller prints `ERR` and returns, with no solo redraft and no component fallback. `finish_capture` closes the recording on the `!ok` path. |
| Accepted prefix | No commit is recorded. The draft graph stays entirely before acceptance. |
| Default OFF | The flag is latched; any value other than ON gives text-identical OFF statements. The `bool ok = [&]{\u2026}()` wrapper with a shadowing inner `ok` is valid C++, at most a `-Wshadow` warning. |
