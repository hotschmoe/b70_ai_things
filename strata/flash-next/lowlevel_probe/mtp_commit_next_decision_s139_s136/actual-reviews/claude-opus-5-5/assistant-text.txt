PROPOSAL 1: QSA COMMIT INDEXER GROUPING. Source GO; a private GPU check first.

Observations (source):
- Inside `capture_commit_batch`, each QSA layer and owner group issues one `native_qsa_indexer_append` per proposed row, 72 per C2 commit (12 layers \xd7 6 rows).
- `native_qsa_indexer_append` is already `append_steps(..., n_steps=1, ...)`.
- The keep vector entries `commitb_ + row*CB + 2 + (u-first)` are contiguous int32, so pos_stride = 1 is valid.
- The raw rows `idx_raw_L_ + (qsa_index*MT + u)*ID` are contiguous with stride D, which the shape check enforces (`s.idx_dim == D`).

Why the grouping is low-risk:
- The same registered kernel image (`append_182f95<false>`) runs the per-step body. Only the runtime loop count changes. No new device code is compiled.
- **Within a step:** each thread d writes and reads only its own column of tail, dead and pooled; block_pos is written by d == 0. Positions are uniform across the work-group, so the inner barriers are reached in converged control flow.
- **Across steps:** the end-of-step work-group barrier (global and local fence) orders step k's tail writes before step k+1's reads. Today that ordering comes from kernel boundaries.
- Rejected rows are trailing (keep is -1 beyond n) and are skipped on the device in both forms.

Inference: about 48 fewer tiny kernel nodes per commit graph. The actual saving is unknown.

Small conditions:
- **Selection:** a latched default-OFF flag read before the first `capture_commit_batch`. The commit graph cache key (rows, S, hbase) does not include the mode, so the mode must not change within a process.
- **Scope:** group only the contiguous run `[first, t)` per owner. Keep the `tail_snap_b_` copy before the call, the per-owner `QsaState` buffers, the GDN commit, the PLE history restore, and the error path exactly as they are.
- **Private GPU check (no model):** one tiny leaf that links the existing kernels archive and compares `append` \xd7 n against `append_steps(n)` on identical starting tail, dead, pooled and block_pos buffers. Cases:
  - n = 1..6;
  - a block boundary crossing (slot R-1);
  - pos = 0;
  - trailing \u22121 rejects;
  - partial keep;
  - two independent owners;
  - eager and graph A/B/A.

  Pass requires full-byte equality of all four buffers plus guards and read-only raw, pos and gamma. Stop at the first mismatch.

  This is the only direct evidence of indexer state bytes; served exactness alone checks them only indirectly.
- **Then:** the main source change, an incremental build (the expected actions are the verify.cpp compile, the engine archive and the link; confirm with a dry plan), and one same-binary OFF/ON matched serving comparison with the existing gates.
- **Preservation:** true RAM eviction and recovery, restore of accepted state, and PLE/history restoration are untouched by construction (only the commit graph's append calls change). The serving comparison must still pass its functionals.
