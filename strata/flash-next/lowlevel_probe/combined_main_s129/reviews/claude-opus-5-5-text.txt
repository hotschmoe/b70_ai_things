SOURCE EVIDENCE (accepted)

Q5 V2:
- **Device body.** The new apply and kernel bodies are the S128-passing private bodies with function renames only. They reuse the production `WideQ5K::load`, block types, `ld_q8_16` and `dp4a4`. There is one new class and one `<WideQ5K,2>` instantiation, and the original Q4K/Q5K apply, wide kernel and launch are untouched.
- **Dispatch seam.** It is reached only from `native_mmvq_head`, after the unchanged RPW2 branch (which keeps priority) and before the unchanged fallback. Conditions: type 13, N 2560, M 248320, C2, wide-K, RPW 1, and a parsed nonzero word. V2 adds the same five validations as the RPW2 branch.
- **Parsing.** The value is parsed on the host and latched in a non-constexpr static. An invalid value throws on the first eligible call, which in practice happens during capture and lands in the existing error path. There is no automatic fallback.
- **Scope note:** `native_mmvq_head` is also called by the verifier head with T columns, so verifier windows with T = 2 select the candidate as well as the MTP pair tail. Whether verifier windows with T = 2 occur in the matched run is unknown. The native-work and output gates cover both callers; just do not describe the effect as MTP-only. Solo MTP heads (C1) are not eligible.

S127 V2 implements the required corrections:
- ON readiness calls `wait_and_throw` on both `cs_` and `side_`.
- The `std::exception` handler drains when ON and rethrows when OFF.
- Drains happen before building the error string.
- The static audit's findings are accepted: no unkeyed mutable global device scratch on the head-free paths, and about 850 KiB of HC allocations keyed per queue may be materialized lazily for B's queue. The lazy `malloc` without a null check remains an error and health concern, not a reason to retry.

Cache option: an empty-by-default CMake option that appends only `-allow_caching -cache_dir \u2026` to the existing single backend argument. Frontend flags are unchanged.
