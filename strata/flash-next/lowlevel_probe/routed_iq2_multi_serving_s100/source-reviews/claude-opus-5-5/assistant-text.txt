# S100 review: STRATA_IQ2XS_MULTI integration patch

## Disposition: ACCEPT

This accepts the patch for main apply, then one IQ TU, archive and AOT rebuild, then the actual OFF/ON metadata, image and resource review. GPU stays with root.

## What the source review supports

- **Arithmetic.** The `Multi<17>` body matches S98 byte for byte: the q2 shifts, grid/sign/SWAR, NW8 split at 4, the signed truncating `finish`, and the separate `d` statement. K stride 8 and XOR 4/2/1 come from the unchanged `row_entries` and `lanes_sum`.
- **Default safety.**
  - `has=false` keeps `kEntryMulti<17,*>` false, so the DOWN path and the alternate `row_dot_multi` overload, which uses `Split` rather than `Multi`, cannot activate.
  - The new bool defaults to false, so the registered name of the existing `native_gu_port` is unchanged.
  - The `static_assert` confines forcing to 17/8/KM.
- **OFF path.** It falls through to the unchanged KqSplit and `launch_gu_port` code.
- **Capture.** The process-latched static is thread-safe, and the `fprintf` is host-side, so it is safe during graph capture. WG/SG/gx/root-sync and output ownership all match.

## Conditions

1. **Prove reachability, the S93 lesson.** The S97 runtime name was `launch_gu_port<17,8,true>`. Trace the actual argv to `launch_gu` to `launch_gu_lanes` to `gu_port_km<17,8>` with the current flags. In particular, show that the `g_old_kernels` and `g_split_multi` branches skip `gu_port_km` under production settings. The caller proof covers the consumers of `Multi`, not this dispatch path.
2. **FP contraction parity.** S98 used `-fp-model=precise`. After inlining, `s[e] += d*sumi` is a candidate for FMA in both the original and the candidate. Confirm the main IQ TU flags. In the rebuilt OFF and ON images, check that the accumulate uses the same instruction form (mad vs mul+add) in both. If they differ, HOLD: the bytewise equality S98 established would no longer carry over.
3. **Resources.** The rebuilt ON image must show the 4 gathers hoisted, 32/16/8 DP4A, SIMD32 at GRF128, and no added spill or scratch fields. In the OFF image, the original port's name and resources must be unchanged. Root has already said exact image bytes are not promised.
4. **Marker scope.** The marker must appear once with ON and be absent with OFF. It proves host selection only.

## Corrections to unsupported inference

- **The \u221240.6% is not a serving estimate.** It comes from a warm, cache-resident two-expert fixture with synthetic group sizes 1\u20136. Singletons gave only about \u22121.2%.
- **Real C2 decode** has about 2 slots \xd7 3 rows. Routed GU17 groups are probably dominated by 1\u20132 entries, so the E4 path may rarely fire. The actual route-size distribution is unmeasured, so expect a small end-to-end effect. A null result would be plausible and should not be called a regression.
- S98 does not qualify other lanes, formats, shapes or streaming-cache behaviour.

## Smallest matched C2 comparison

Root's design is right:

- Same binary, flag 0/1, all other candidates OFF, fixed config.
- One warm-up plus 3 matched coding pairs per arm.
- Strict text/SSE/usage/native-work/draft/capture gates.
- Normal QUIT, CID and name gone, wrapper exit 0, full health.

Two refinements:

- **Interpreting a draft-count mismatch.** S94 showed `draft_n` varying across processes on the baseline path (207 vs S93's 205). Keep the stop on mismatch. But record any mismatch as "unresolved cross-process", not as a candidate defect, unless the text or accepted work also diverge. The candidate is bitwise-exact by source plus S98.
- **Report scope.** Report the per-pair per-stream decode figures descriptively only. With three pairs, make no gate or percentage claim. The 150 tok/s per stream target remains unmet regardless of the outcome.
