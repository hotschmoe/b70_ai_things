**ACCEPT the private CPU-only adapter build.** No blocking bug. The GPU step stays gated on the compiled image, FP and resource checks the contract already lists.

**Byte reconstruction and bounds**

- The candidate reads five dwords from the address rounded down to four, then applies the same 16-bit funnel as the original helper. Little-endian provenance is exact: the unaligned case selects bytes 2 to 17 of the 20-byte window, the aligned case bytes 0 to 15. The root byte check agrees with my reading.
- Block stride is 210, so block starts alternate between 0 and 2 modulo 4. Rows start aligned for both pinned shapes because 24 and 10 blocks per row give row strides that are multiples of 4. The only below-start read is the two-byte scale field of the preceding block, which never happens on the first block of the allocation. The highest read ends at offset 195 of a block, inside the 210-byte block, so the last block of the tensor never reads past the allocation.
- The host guard enforces base alignment and the two shapes. That guard is what makes the row-start argument hold, so any future shape must re-prove it before the guard widens.
- The aligned case still loads a fifth dword it does not use. Harmless, but it is a visible ISA artefact: expect five dword loads, not four, in that path.

**Arithmetic ledger**

Downstream of the two reconstructed words nothing changes: same shift and mask, saturating byte subtract of 32, same four plus four dp4a per column in the same order, same half to float, signed scale product, int to float, scale product and accumulate, and the same XOR tree. The S85 packed centering branch is gone from both arms. The original arm is byte-identical to the S85 original, which is the S102-proven main image computational prefix, so the private original and the public kernel are both valid anchors.

**Post-build gates before any GPU lease**

1. Candidate ISA: the offset-selection chain from the original must be absent, replaced by dword-aligned sends. If the compiler reintroduces a byte gather or splits the loads, HOLD.
2. Same 48 dp4a, same multiply, multiply-add and add pattern as the original for the FP tail, same conversion points. A different contraction pattern is a HOLD, since precise mode still permits contraction.
3. SIMD32 and GRF128 retained; any resource change inspected. Missing spill fields are not zero.
