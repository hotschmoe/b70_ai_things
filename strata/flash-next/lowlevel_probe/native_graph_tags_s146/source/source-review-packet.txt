samples only, TWO per cell of arm{control,candidate} x tags{OFF,ON}:

qualification. Every sample resets BOTH armstates from seed outside timing,
uses existing completionwait, checks COMPLETE selectedownerstate bytes/finite/
guards plus ALLinputs/unusedz/gamma/outputsentinel read-only checks. No hashes
replace byte comparison. Prior S145ABA/keep1..3/continuation strict campaign is
reused; no claim this method reruns those cases. No secondtoytest is proposed.

submit begin tag, separately bracket ONLYgraph.replay() hostreturn, optionally
submit end tag, then q.wait_and_throw(), end completedwall clock. All event
queries and state/read-only/guard readbacks happen AFTER that wait/wallendpoint.
Capture itself is unchanged; tags are OUTSIDE graphcapture. Two tags only per
ONmeasurement, none pernode. Hostclockcalls and existing queuewait are common.

Tagged measurement reads begin.command_end and end.command_start, requires
end>begin, stores both uint64 nanoseconds and their difference. OFF fields are0
AND device_envelope_valid=false (no fake device measurement). Same-devicequeue
DOMAIN only; no hostdeviceclockbridge, command_submit query, occupancy, per-op
service/data-readiness/physicalidle/traffic or servinggain claim. Envelope may
include graph dependencies, queuegaps and tagboundaries. No graphprofilingfinalize
property or queueenable_profiling is added; no runtimeadapter/driver override.

Report ALL8 rows, bothcellwall medians/ranges and hostgraphsubmit, taggeddevice
envelopes; two samples/cell cannot establish significance/noiseband/stability.
Any method overhead is descriptive completedwall ONvsOFF, not assumed negligible.
A changed graphsubmit bracket alone is not a completechain optimization. The
large public/private deviceenvelope difference, if any, is the EXISTING S145
kernel mechanism; S146 adds no arithmetic improvement and forecasts no serving.

Future execution -> Root binds actual S145 strictPASS/buildreceipt/newhostEXE
identity and reuses existing finite lease/lifecycle/fullstate/health conventions.
No new generic runner is written here. Root supplies onecard+physicalPCI pin,
STRATA_GDN_SPLIT0/STRATA_GDN_COMMIT_SPLIT1/STRATA_DBG_GDN0, NOpreload/unitrace/
URloggers, and --native-tags. Unsupported3 is an explicit normalcapability stop
for root to review, not an automatic fallback/retry or a numericalfault whitelist.
Any thrown API/numeric failure native1 preserves evidence/drains existing RAII;
root decides cleanup/health as in S145, never automatic force/reset/retry.

Verification -> Exact source projection and inverse diff, shellsyntax, executable
