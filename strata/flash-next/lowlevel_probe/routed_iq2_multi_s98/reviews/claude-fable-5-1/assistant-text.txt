**Arithmetic review, source against source**

The candidate is exact by construction and I found no arithmetic defect:

- Code extraction, codebook gather, sign unpack and both SWAR forms are the same expressions as the original dot. No uint16 to int2 punning is reintroduced.
- The eight products feed two integer chains split at four, in the same order, through the same signed dp4a. The integer bound argument in the S97 ledger holds, so no overflow.
- The finish keeps both truncating signed divisions and the explicit split of the half-to-float scale product before the final float multiply. Nothing is reassociated.
- Per lane, the K loop visits the same ten blocks in ascending order, each entry accumulates from zero in that order, and the XOR 4, 2, 1 reduction is unchanged. Lanes stay inside their eight-lane group of the 32-wide sub-group.
- Activation reads moved into the per-entry step read exactly the block and scale the original read. Repeated tokens alias read-only input, which is legal.

**Alias and output ownership**

Only lane zero writes, each entry writes its own row in its own plane, and the group loop never crosses a group boundary. Natural E4, E2 and scalar tails cover sizes one to six, singleton and zero correctly. The fixture poisons inactive entries and the whole down output, checks all guards and read-only arrays after every snapshot, and refuses export overwrites. Snapshot and timing counts in the leaf match the analyzer exactly.

**Host-binding and fixture defects to resolve in metadata review**

1. **Public anchor identity is not proved by the build script.** It hashes the frozen kernels archive, but the runtime identity asserts a specific object member hash. The review must extract the IQ object from that archive and confirm it equals the member the S97 audit disassembled. Without that, the anchor may be an older kernel and the "public equals original" equality means less than claimed. This is the one real blocker for the metadata step.
2. **Device image provenance.** The public phase 1 images come from the S59 prelinked images object, the candidate from the new one. The review must show both registered names, their distinct host info records and their image ownership, as the root packet already requires. Symbol names alone do not settle it.
3. **Anchor indexing assumption.** The fixture assumes phase 1 gate and up are indexed by entry, not by destination. The S97 ledger supports that reading. If it is wrong, the strict comparison fails loudly, so this is a cost risk, not a silent one.
4. **Root sync property inside graph recording.** The private launch copies the public property. If graph capture rejects it, the run exits before graph phases. Eager correctness already runs first, so that evidence is retained either way.
5. **Public call signature.** The last argument passed to the public grouped entry is the grid group count. Confirm that parameter meaning once in the review, since a mismatch changes which groups the anchor computes.

**Scope**

Keep the three layouts, two inputs and the captured A, B, A replay. The singleton timing is worth keeping as the resource regression discriminator for the extra template body. Nothing else should be added, and the eager repeat pass is cheap enough to leave. The 300 second container timeout is adequate for the stated 11 second decoder class of work.

**Evidence limits**

A pass proves byte equality of the candidate against the public anchor on real weights for one expert pair, and gives interval timings on a warm two-expert aliasing fixture. It does not measure routing reuse, cache behaviour or serving. If the multi arm is strict and not faster, the hoisting mechanism is closed and should be recorded as such. If it is faster, the result still carries no serving prediction and no cache qualification.

Nothing here warrants a format or lane sweep, a full parity run, or a percentage cutoff.
