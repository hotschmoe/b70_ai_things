# Independent review: S93 post-mortem, S94 caller-only patch, decode-trace proposal (2026-10-15)

All three dispositions below come from frozen packet evidence only. I ran no tools, builds or GPU work.

## 1. S93 disposition

**FAILED_ACTIVATION / CANDIDATE UNREACHABLE IN PRODUCTION CALLER.** It is not neutral, not a regression, not a numerical failure and not a hardware fault. The executed evidence establishes three things:

- **What was measured:** OFF and ON matched on request, output, SSE, usage and native work for 6 responses: 2 coding at 107/256, 3 at 4K and the first at 32K. The ON arm always ran the baseline kernel, because the host marker count was 0 in both arms.
- **What this does not show:** these matches say nothing about the candidate kernel's serving correctness, speed or effect.
- **Why the guard was false (source-proved):**
  - The argv has no `--kv-resident`, so `kv_resident` is 0 (`generate.cpp:472`, `:2351`).
  - `kv_plan` therefore returns early with mode 0 and slots equal to pages (`layer.cpp:727`).
  - That sets `st.kv_mode = 0` (`:793`), so `staged = st.kv_mode == 1` is false (`prefill.cpp:3077`).
  - The `value_domain` guard is false for every chunk.

S92's private 36-case numerical PASS and the S93 metadata/image audits remain valid as kernel evidence. They never covered caller reachability.

## 2. S94 CPU source-apply/build: conditional GO

The source reasoning supports the new mode-0 term:

- **Identity page table:** mode 0 builds `tab[i]=i`, uploads it, waits, then waits on the device queues (`layer.cpp:966-977`).
- **Pools:** the non-staged path uses `qsa_attn_pools(st)` with `st.page_table` (`prefill.cpp:3302`). `qsa_kv_resolve` is a no-op unless mode is 1 (`layer.cpp:1033`), so no streaming resolve is skipped.
- **Ordering:** `kv_append` into the resident pools is enqueued on `m.cs` before attention on the same in-order `m.cs`.
- **Exclusions:**
  - Ring/drafter pools are excluded because the drafter is mode 2.
  - Elastic pools are excluded by `kv_elastic < 0`. Elastic is also impossible here, since `--batch 2` forces kv-grow off (`generate.cpp:3940`).
  - Hybrid and Q4 KV are excluded because `st.kv_int8` is false for them.
- **Unchanged parts:** the math, wrapper and attention TU are untouched. Reusing the attention object and archive byte-exact is appropriate. Not rerunning the 36 numerical cases and CAP2051 seeds is justified.

**Conditions before apply.** These are source reads only. They close the actual S93 lesson: trace every conjunct of the guard, not just the one that failed.

1. **`st.n_pages` assignment.** It is not shown in the excerpt. Confirm it is set to `p.pages` in `qsa_state_init` or a sibling. If it is unset or 0 for mode 0, the new term is dead.
2. **Batch-slot states.** Confirm the `st` used at `prefill.cpp:3077` for `--batch 2` slots goes through the same `qsa_state_init` mode-0 identity path. `generate.cpp:3939` says batch slots "carve their own K/V". Prove their `page_table` is identity, their `kv_elastic` is -1, and their slots are at least their pages.
3. **Remaining conjuncts under the actual argv:**
   - `m.attn_batch == 32`.
   - `m.cap == 2051` in production at 32K.
   - The first width reaches cap within the 12288-token prefill chunks.
   - `old_attn` is false and `qsa_prompt_attn_batch` returns false. XMX defaults off via env (`xmx.dp.cpp:370-371`), but the CUDA/HIP-neutral branch around `:2011` must also be confirmed to fall through on SYCL.
4. **Pool layout equivalence.** The resident INT8 pool layout (strides, scale layout, `kv_rot`) must match what S92 validated through `pools_of(m.stage, ident_table)`. Slots equal pages, so this is expected, but S92 only exercised the staged pool object. Write this down explicitly.

If all four close, I recommend **GO** for:

- applying the patch and building only the prefill TU, the prefill archive and the main AOT link;
- then the final host-metadata and image-ownership recheck, with exact image-hash reuse.

If any one fails, **HOLD** and do not build.

The header comment fix is documentation only. Do not rebuild the attention TU for it.

## 3. Future GPU gate (separate, not approved here)

The future gate stays as the packet describes it:

- Same new binary for both arms, with the 107/256 C2 warm-up unchanged.
- The same strict request, output, work, functional and health gates.
- No changes to tolerances, no daily restore and no profiler during the clean measurement.

Add an **activation assertion on the first request that the source shows is eligible.** Use the conjunct trace from \xa72 to name that request. If the 4K requests never reach width 2051, the first eligible request is the 32K one, and the 4K requests are not activation evidence. A missing marker should stop the arm immediately. A full 200k/cache rerun is not needed for this discriminator. Full cache qualification is still required later for any candidate selected as a winner.

## 4. Wasted dev-loop work

- **Main build plus serving launched before a caller-path proof.** The argv \u2192 planner \u2192 state \u2192 guard trace is about 10 lines of source. It should have been the first gate after S92. The 174 s link, the 14 s static binding, and both serving arms (about 4 minutes of GPU lease) bought only a reachability negative.
- **ON 3\xd74K run before activation was checked.** The 4K requests ran with the marker absent and were only "recorded". Either they are ineligible, which the source would show, or they were the cheapest possible early stop. Either way, gate on the first request that should fire.
- **Not wasted:** stopping at the early 32K gate, no retry, normal teardown, and keeping the failed result.

## 5. Decode C2 trace audit: usefulness

- **Assessment:** sound and well-scoped. It uses existing tools, one fresh server, `VERIFY_PROFILE` absent, ring-drain and race handling, honest limits on the clock bridge, no additivity claims, and no repeats of the rejected S7/S38/S79/S80 runs.
- **Priority:** for the stated goal (\u2265150 tok/s per stream against about 54\u201356 now, and concurrency), this decode trace is the higher-value next GPU step. S94 only touches prefill attention and cannot move decode or per-stream rate.
- **Sequencing:** order it after the S94 serving decision as proposed, but do not let it wait on the S94 conditions if those stall.
- **Caveat to keep:** the trace is an attribution census only. It does not qualify any gain or prove causality for the shared-expert fork.
