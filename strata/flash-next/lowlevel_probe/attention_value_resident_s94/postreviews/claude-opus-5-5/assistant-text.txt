## Evidence limits

- The host marker shows the candidate path was entered once. It does not count GPU dispatches or show which layers used it.
- Identical output and identical accepted count (136) do not prove internal state equivalence.
- The cause of the 207/205 split is unresolved. Do not record it as a numerical failure, as harmless nondeterminism, or as a regression.
- **Context root should record, but not use to relax the gate:**
  - The S93 baseline-path arms (ON was inactive) both offered 205 on this same p4096-0 request.
  - The S94 OFF arm, a different binary on the same baseline path, offered 207.
- So the offered draft count already varied across processes on the baseline kernel. That makes it a fragile strict discriminator. It does not clear the candidate: no OFF/OFF control in the same session exists.
- The synthetic 36-case and CAP2051 numerical proofs remain valid kernel evidence. They do not certify actual production pools.

## Dev-loop lessons

1. **S94 itself was efficient.** It was a caller-only change, reused the attention object, archive and images byte-exact, rebuilt only one TU plus the link (175 s), skipped any numerical rerun, and aborted at the first gate in about 7 s of client time. The remaining cost was mostly lease, health and teardown overhead.
2. **The real gap is gate design.** A strict equality gate on a quantity never shown to be repeatable baseline-vs-baseline turns noise into a hard stop. Two rules for any future identity gate:
   - Before using a native counter like `draft_n` as a strict gate, establish whether it repeats across processes, from existing logs where possible.
   - Otherwise gate on output, usage and accepted work, and treat offered drafts as diagnostic only.
   - Do not apply either rule retroactively to S94.
3. **The prefill payoff ceiling was low.** The upside is bounded to one attention sub-stage of prefill and does not touch decode or per-stream rate, which are the unmet goals (about 54\u201356 vs 150+ tokens/s per stream). Parking the branch is the right allocation, not just caution.
4. **Do not reopen without a reason.** Reopen only if a future trace shows 32K prefill attention as a dominant bounded cost. Even then, start with the repeatability control above, not a rerun.
