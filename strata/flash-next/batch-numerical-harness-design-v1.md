## API source boundary, cancellation and migration

batch_api_trace_v1.py imports the actual pinned API and wraps its existing IO
and generators. It makes one native producer stdout/stderr stream before the
real API readers, recording exact commands and outputs with process/request-local
call attribution. It preserves scheduler/cache/sampling/model arguments and
returned pipe bytes. Diagnostic IO can change timing; diagnostic-off controls
are mandatory before any performance or race-absence claim.

batch_api_client_v1.py submits real simultaneous local HTTP/SSE cohorts with a
barrier and bounded deadlines. A selected client's socket/reader closes after
actual content. A successful transport does not prove native cancellation: the
actual trace must show corresponding native STOP/BSTOP, final ownership/drain
and healthy isolated peer results. Concurrent client sends do not prove GPU
multi-row overlap; actual completed native events and per-request producer frames
are required.

batch_api_prefixes_v1.py reconstructs every native segment of a request. Later
GEN/BGEN submissions must equal the first actual submitted IDs plus ALL prior
native generated IDs; prior segments must be terminal. Exact per-source token/
position and every raw layer/head bind to that segment, not a guessed output-only
migration history. Observer26 phase2 and its full raw collector are needed for
actual postmigration main-session heads/residuals. Never mark migration math
qualified from output IDs alone.
