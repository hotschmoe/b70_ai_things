## Correctness points to flag (none blocking; disclose, don't fix now)

1. **Non-MTP `--batch` output changed.** Both emitters now always append the two counts, so plain `--batch` without `--batch-mtp` prints `... 0 0`. The server then reports `draft_n: 0` as a known zero where it was previously absent, unless the admission reported drafts. This is arguably accurate (batch slots offered no drafts), but the engine's stdout protocol is no longer byte-identical on that non-MTP batch path. AGENTS.md asks for the default path to stay byte-identical, so either:
   - (a) document "always `0 0` without `--batch-mtp`" (recommended; no source change), or
   - (b) emit the counts only `if (batch_mtp)`. This changes both emitters, and AGENTS.md then requires building CUDA and SYCL. I would not do it unless asked.
2. **"Accepted" means verify-accepted, not emitted.** `drafts_accepted += keep[b] - 1` is added before the emit loop, which can `break` on stop or length. A draft accepted on the final window can therefore be counted even when its token is not emitted, so accepted can exceed what actually reached the client by at most 1 per request. Say so in the doc row rather than changing the math.
3. **Minor CUDA/SYCL asymmetry on non-finite logits.** CUDA increments `offered` before the non-finite check and `accepted` after it, so a non-finite window counts as offered and not accepted. The SYCL batch-MTP loop has no non-finite branch. Leave as is; it is consistent with "offered".
