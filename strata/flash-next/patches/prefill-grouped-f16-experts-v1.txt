RESULT -> SOURCE ONLY. No compiler, GPU, model weights or native execution used.
The local bundled DPCT detail/blas_utils_detail.hpp:372-413 establishes the
grouped oneMKL interface; blas_utils.hpp:1203-1210 instantiates FP16 inputs and
FP32 outputs/scaling. Existing Gemm::f16 uses trans/nontrans, alpha=1, beta=0,
FP32 compute and the descriptor's math mode. This patch uses those same choices
with group_count<=8, group_size=1 and independent per-expert row counts.

Each decoded expert needs GU 1280*2560*2 plus down 2560*640*2 = 9,830,400 bytes.
Eight slots need 75 MiB instead of 18.75 MiB: delta 58,982,400 bytes / 56.25 MiB.
Both actual allocation and bytes_needed use the same default-off slot selector.
No extra device scratch is added by this code beyond those six extra slots;
oneMKL internal workspace is not bounded by this accounting. Host metadata is
bounded to eight groups per submitted operation and retained through its event.

For each routed expert the original native dequantization and source-blob release
event remain. Its rows retain original expert offsets. A full group or final tail
submits grouped GU, then the existing SwiGLU per expert in original group order,
then grouped down. Original combine/scatter is unchanged. Reuse of a decoded slot
is ordered after down on the required in-order queue. Streamed/resident experts
use the same pending slot count; skipped streamed entries do not create holes.

No normal explicit wait is added. Metadata lifetime uses the bundled DPCT
event-dependent host_task pattern. This may add CPU queue overhead; failure-only
queue retirement preserves metadata after a failed submission. BLAS can choose
different tiling/accumulation for grouped calls: neither bitwise equality nor a
speed improvement is assumed. Quantization formulas, FP16 intermediate storage,
router, shared expert, SwiGLU expression and scatter order are preserved.
